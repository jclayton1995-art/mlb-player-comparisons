# Comps — MLB hitter comparisons on underlying skills

A comparison engine that finds the hitter-seasons most like a given one using only
*underlying* data (contact quality, batted-ball shape, approach), then projects next
season from what those comps did next. The React UI is a pure view over the model.

## Run it

```bash
cd ~/Documents/Claude/Projects/MLB\ comparison\ app
pip install -r requirements.txt        # once
python scripts/train_model.py          # ~20s; rebuilds data/model/* from data/processed/*
./run.sh                               # starts http://localhost:8000
```

`run.sh` just runs `uvicorn server.app:app --port 8000`. The built frontend is in
`frontend/dist`, so Node is not required to run the app.

## Update the data

```bash
python scripts/refresh_data.py             # pulls 2025 + 2026, enriches all seasons
python scripts/refresh_data.py --years 2026
python scripts/train_model.py              # then retrain
```

`refresh_data.py` needs internet (Baseball Savant + FanGraphs via pybaseball). It
replaces the requested seasons in `data/processed/*.parquet` and adds FanGraphs
context columns (age, ISO, BABIP, wOBA, WAR, HR, SB, extra plate-discipline splits)
to every season. The model picks up `age` automatically once it is present.

## How the model works (short version)

1. **Season-relative z-scores.** Every metric is standardized against its own season's
   league, so 2019 and 2022 barrel rates are compared as "distance from league".
2. **Whitening.** The standardized metrics are rotated into uncorrelated directions
   (PCA, full rank). Exit velo / EV50 / hard-hit% / barrel% collapse into one
   "hits it hard" direction instead of being counted four times. Distance in this
   space is the Mahalanobis distance.
3. **Learned weights.** A ridge regression maps the whitened profile to next-season
   xwOBA, wRC+, K%, BB%, ISO and BABIP. The embedding is
   `[predicted next-season outcomes, 0.3 × whitened profile]`, so comps both *look*
   alike and *project* alike. The 0.3 was chosen by backtest.
4. **Projection.** Kernel-weighted mean of the next seasons of the 40 nearest comps
   that have a next season on record. The band is the weighted 20th–80th percentile.
5. **Backtest.** Walk-forward over test seasons 2021–2024, refitting as-of each year.
   RMSE of next-year wRC+ (hitters with 200+ PA both years, n = 1,069):

   | Method | wRC+ RMSE | xwOBA RMSE |
   |---|---|---|
   | Regression model, no comps | 21.4 | .0269 |
   | **40 nearest comps (this app)** | **21.6** | **.0271** |
   | Old app: hand-weighted z-scores | 22.4 | .0291 |
   | Marcel-style regression to mean | 22.4 | .0273 |
   | Assume same as this year | 25.8 | .0296 |

   Numbers are regenerated by `train_model.py` and shown in the app under
   "How comps are chosen".

## Layout

```
server/app.py            FastAPI: /api/search, /api/players/{id}, /api/compare/{id}/{season}, /api/meta
src/model/prepare.py     raw parquet -> canonical hitter frame, feature catalogue, percentiles
src/model/engine.py      ComparisonModel (standardize -> whiten -> ridge -> embed), CompIndex, projection
src/model/backtest.py    walk-forward evaluation vs naive / Marcel / old method
scripts/train_model.py   fit + backtest -> data/model/
scripts/refresh_data.py  pull new seasons + FanGraphs enrichment
src/data/*               original pybaseball fetchers/mergers (unchanged)
frontend/                Vite + React + TypeScript UI (npm run dev for hot reload, npm run build to ship)
legacy/                  the previous Streamlit app, kept for reference
```

## Frontend development

```bash
cd frontend && npm install && npm run dev     # http://localhost:5173, proxies /api to :8000
npm run build                                 # writes frontend/dist, served by the API
```

## Deploy (Render, free tier)

The trained model (`data/model/`, ~3 MB) and the built frontend (`frontend/dist/`) are committed,
so the host only needs Python. `render.yaml` describes the service.

1. Commit and push to GitHub.
2. On https://render.com → **New → Blueprint** → choose this repo → Apply. Render builds with
   `requirements-server.txt` and runs `uvicorn server.app:app`. First deploy takes a few minutes.
3. The app lives at `https://mlb-comps.onrender.com` (or whatever name you pick). The free tier
   sleeps after 15 min idle; the first visit after that takes ~30 s to wake.

To ship an update: retrain / rebuild locally (`python scripts/train_model.py`, `cd frontend && npm run build`),
commit, push — Render redeploys automatically.
